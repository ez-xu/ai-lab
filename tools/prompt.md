【最重要的一条：今天出什么，不由你决定】
今天的「领域 / 形态 / 载体 / 约束 / 档位」已经由 tools\pick.ps1 按日期确定性抽好了，见下面的「今日抽签结果」。**必须原样使用，一个都不许换。**

为什么这么规定：你（以及任何模型）在自由选题时都有强先验，会反复落回数据库 / 操作系统 /
网络这几个最熟的领域，池子再大也没用。抽签就是为了消掉这个偏差。

所以：

【第二步：出题规则】
1. 两道题分别用抽签结果里题位 A / 题位 B 的「领域 / 形态 / 载体 / 约束」，逐字对齐，不要张冠李戴。
2. 难度：按 PROGRESS.md 的当前档位（默认 L2）；最近 3 天完成度 ≥80% 升档，<50% 降档。
3. 时间盒与提示条数以抽签结果为准：每题的时间盒已经按抽到的档位填进下面的成品模板，照抄即可，不要自己改档位。
4. 档位只缩放深度，不换形态：
   - 微练 = 骨架级：一页以内的草图 / 清单 / 半个签名，不做实现；验收 2 条，提示最多 1 条。
   - 快练 = 轻交付：一页笔记 / 一张对比表 / 一个能跑起来的短实验；验收 3 条，提示最多 2 条。
   - 主修 = 完整交付：形态自带的交付物那样；验收 4 条，提示最多 3 条。
   模板里已经写明本题的提示条数上限，写够、不超过即可。
5. 两题必须能在本机跑：Windows 11 + WSL Ubuntu；可用 python3.12 / node / clang / cmake /
   dotnet / git / pwsh；没有 docker、Windows 侧没有 gcc、没有 cargo/go。
6. A 练眼界（见得多），B 练框架（搭得起），两者不要互相替代。
7. 「载体」决定你从哪里取材，要具体到能点开：写清是哪个项目的哪个文件、哪篇论文、
   RFC 第几号第几节、哪份手册的第几章。不要写"查阅相关资料"；题位 A 还要对上该题的锚点。
8. 「约束」必须体现在验收标准里，不能只写在标题上。例如约束是「必须度量」，验收标准里
   就要有一条要求给出前后数字。

- 每题必须有：为什么练这个（接到眼界 / 框架目标）、起点与输入（具体到文件、关键词、经典系统名、论文标题或 RFC 编号）、交付物（明确路径）、验收标准（条数按档位，见【第二步】第 4 条）、提示（不超过模板写明的上限）。

- 不要在题目里给出完整实现代码，只给方向与提示。
- 不要在题目里另立时间盒或产出深度：照抄下面成品模板已经填好的值，也不要自己写池子的规模数字（池子、档位、形态的清单都只在 tools\pools.json 里，改了那边这边不会跟着变）。
- 题 B 必须包含 DESIGN.md 的产出要求（调用方视角示例代码、接口定义、数据流图、≥3 个 ADR）。
