【最重要的一条：今天出什么，不由你决定】
今天的「领域 / 形态 / 载体 / 约束」已经由 tools\pick.ps1 按日期确定性抽好了，见下面的

为什么这么规定：你（以及任何模型）在自由选题时都有强先验，会反复落回数据库 / 操作系统 /

所以：

{{ASSIGNMENT}}

【第一步：读取上下文】
- {{ROOT}}\CURRICULUM.md  （课程体系：四题结构、领域/形态/载体/约束的说明、能力阶梯、硬规则、本机环境约束）

【第二步：出题规则】
1. 四题分别用抽签结果里对应的「领域 / 形态 / 载体 / 约束」，逐字对齐，不要张冠李戴。
2. 难度：按 PROGRESS.md 的当前档位（默认 L2）；最近 3 天完成度 ≥80% 升档，<50% 降档。
3. 时间盒：A1 45–60 分钟、B1 45–60 分钟、A2 20–30 分钟、B2 20–30 分钟。
   A2/B2 是「快练」，产物必须轻（一页笔记 / 一张对比表 / 一份 ADR），不要出成大题。
4. 四题必须能在本机跑：Windows 11 + WSL Ubuntu；可用 python3.12 / node / clang / cmake /
   dotnet / git / pwsh；没有 docker、Windows 侧没有 gcc、没有 cargo/go。
5. A 练眼界（见得多），B 练框架（搭得起），两者不要互相替代。
6. 「载体」决定你从哪里取材，要具体到能点开：写清是哪个项目的哪个文件、哪篇论文、
   RFC 第几号第几节、哪份手册的第几章。不要写"查阅相关资料"。
7. 「约束」必须体现在验收标准里，不能只写在标题上。例如约束是「必须度量」，验收标准里
   就要有一条要求给出前后数字。

【第三步：写文件】
把结果写入 {{ROOT}}\daily\{{DATE}}.md，严格使用 templates\daily-task.md 的标题层级与区块顺序，中文书写。
要求：
- 每题开头标注：领域 / 形态 / 载体 / 约束 / 难度 / 时间盒，与抽签结果一致。
- 每题必须有：为什么练这个（连接到眼界/框架目标）、起点与输入（具体到文件、关键词、经典系统名、论文标题或 RFC 编号）、交付物（明确路径）、3–4 条客观可检验的验收标准、不超过 3 条提示。
- 主修题（A1/B1）另需 1 个进阶挑战；快练题（A2/B2）不需要进阶挑战。
- 验收标准必须客观可检验（能跑命令、能对比输出、能观察现象），禁止「理解 X」「掌握 Y」这类无法验收的表述。
- 题目要具体到能立刻动手，禁止「学习 X 框架」这类泛泛表述。
- 不要在题目里给出完整实现代码，只给方向与提示。
- 题 B1 必须包含 DESIGN.md 的产出要求（调用方视角示例代码、接口定义、数据流图、扩展点清单、≥3 个 ADR）。
