## 题 A1（广度 · 主修）｜ 拆开 SQLite 的查询计划：一条 SQL 是怎么从全表扫描变成索引查找的

**领域**：数据库与存储（1 号池） ｜ **形态**：A1 拆经典 ｜ **难度**：L2 ｜ **时间盒**：45–60 分钟

### 为什么练这个
SQLite 是全世界部署量最大的数据库，而它的查询优化器就藏在 `python -c "import sqlite3"` 里，零安装、零配置。把这一个优化器拆开看一遍，你以后遇到任何慢查询，第一反应会是"先看计划，别看代码"——这个反射能省掉你后面几年的瞎猜。眼界目标：见过一个真实优化器的内部表示（VDBE 字节码），而不只是听说过"索引会变快"。

### 起点与输入
- 语言 / 工具：`python` 3.12（内置 `sqlite3`，本机 SQLite 库版本 3.49.1）。**不需要安装任何东西。**
- 从哪里开始（三条命令就是全部入口）：
  - `EXPLAIN QUERY PLAN <sql>` —— 给人看的计划摘要
  - `EXPLAIN <sql>` —— VDBE 字节码，一行一个 opcode
  - `PRAGMA index_list(表名)` / `PRAGMA index_info(索引名)` —— 索引长什么样
- 检索关键词：`covering index`（覆盖索引）、`leftmost prefix`（最左前缀）、`VDBE opcode`、`sqlite_stat1`
- 参考材料：SQLite 官方文档 *EXPLAIN QUERY PLAN* 与 *The SQLite Bytecode Engine*（`sqlite.org/opcode.html`）
- 工作目录：`C:\Users\15854\ai-lab\daily\2026-09-23\A1\`

### 交付物
1. `daily\2026-09-23\A1\probe.py` —— 可重复运行的脚本：建表 → 自己生成 ≥20 万行合成数据（**别下载数据集**）→ 依次打印 5 种情况的 `EXPLAIN QUERY PLAN` → 打印两种情况的耗时（预热后取中位数）
2. `daily\2026-09-23\A1\plans.txt` —— `probe.py` 的完整输出重定向存盘（原始证据，不许手抄、不许删减）
3. `daily\2026-09-23\A1\NOTES.md` —— 机制笔记（≥5 行）+ 字节码对照 + 两组耗时数字

### 验收标准（每条都要能跑命令或对比输出）
- [ ] `python probe.py > plans.txt` 退出码 0；`plans.txt` 里同时搜得到 `SCAN` 与 `SEARCH`（`Select-String -Path plans.txt -Pattern 'SCAN|SEARCH'` 有命中），且至少一条计划含 `USING COVERING INDEX`
- [ ] 违反最左前缀的那条查询（复合索引建在 `(a, b)` 上，但只按 `b` 过滤）在 `plans.txt` 里仍然是 `SCAN`；把那一行原样贴进 `NOTES.md`
- [ ] `NOTES.md` 贴出加索引前后**同一条查询**的耗时中位数（各 ≥5 次，去掉第一次冷启动），后者比前者快 **≥5×**；若不足 5×，把行数加到 100 万重测并在笔记里写明原因
- [ ] `NOTES.md` 有 ≥5 行机制说明，且包含三件事：① ≥5 个 VDBE opcode 各一句作用；② 指出哪些 opcode **只在索引查找时**出现、哪个**只在全表扫描时**出现；③ 用你自己的话说清「最左前缀」和「回表」在这题里各对应哪一段输出

### 提示（最多 3 条）
1. 先只跑 `EXPLAIN QUERY PLAN`，别一上来就调优。`SCAN <表名>` 就是全表扫描，`SEARCH <表名> USING INDEX ...` 才是索引查找——这两种字符串是你后面所有判断的锚点。
2. 计时用 `time.perf_counter()` 包住 `execute(...).fetchall()`；第一次执行有冷缓存，先跑一遍丢掉再取 5 次中位数。造数据用 `executemany` + 一次 `commit()`，别一行一个事务，否则 20 万行能跑很久。
3. `EXPLAIN` 和 `EXPLAIN QUERY PLAN` 是两个不同的东西：前者给 VDBE 字节码，后者给人类可读的计划摘要。两个都要看，笔记里要能把它们对应起来（"这一行摘要对应哪几条 opcode"）。

### 进阶挑战
- 跑一次 `ANALYZE`，然后 `SELECT * FROM sqlite_stat1` 看优化器手里到底有什么统计信息；接着构造一条"优化器选错索引"的查询（提示：范围条件 + 排序混在一起），贴出它的 `EXPLAIN QUERY PLAN`，再用 `INDEXED BY` 强制指定索引重跑，对比两次的计划与耗时，并写清优化器为什么会选错。

## 题 B1（框架 · 主修）｜ 给一堆各写各的采集脚本定一个管道接口

**形态**：B1 接口设计 ｜ **难度**：L2 ｜ **时间盒**：45–60 分钟

### 为什么练这个
你手上会不断出现"从某个地方读数据、处理一下、写到另一个地方"的脚本，每一个都在重复循环、重试和输出格式。框架能力的第一步，就是在写第三个之前停下来，把**记录的形状、失败语义、生命周期**这三件事定死。这题逼你先写调用方代码、再倒推接口——顺序反了，设计出来的接口一定是从实现漏出来的，而不是从使用长出来的。

### 场景（模糊需求，这是故意的）
> 你手上有三个采集脚本：一个从串口读一行 CSV（`时间戳,值`），一个每秒轮询一次 HTTP 接口拿 JSON，一个 `tail` 本地日志文件。三份代码各写各的 `while True`、各写各的 `try/except`、各写各的输出格式；每加一个新数据源就要复制粘贴一遍。
>
> 把它们收成一个**采集管道框架**，硬要求：以后加一个新数据源、或加一个新输出目标，只需要新写一个文件，**不动框架代码**。
>
> 下面这些边界**故意没定**，由你定，而且每一条都要给出理由：
> - 一条采样记录长什么样？（字段、类型、时间戳语义：采集时刻还是设备时刻？）
> - 重试的语义是什么？（重试谁、几次、间隔怎么涨、重试期间的数据丢不丢）
> - 下游比上游慢怎么办？（背压 / 丢数据 / 缓冲，选一个，并说清代价）
> - 生命周期谁管？（`start()/stop()` 还是上下文管理器）
> - 配置从哪来？（代码里写死 / 传字典 / 读文件）
> - 一个数据源挂了，其它数据源还跑不跑？
>
> （**不需要真串口和真 HTTP**，用假的源实现就行——接口设计才是重点。）

### 交付物
1. `C:\Users\15854\ai-lab\daily\2026-09-23\B1\DESIGN.md`，必须含：
   - **调用方视角的示例代码**（先写这个，再倒推接口）
   - 接口定义（真实签名，带类型标注）
   - 数据流图（文本图即可）
   - 扩展点清单
   - **≥3 个 ADR**：选了什么 / 放弃了什么 / 为什么
2. 最小可运行实现：`daily\2026-09-23\B1\pipeline\`（能 `python run_demo.py` 跑起来）
3. 扩展点演示：`daily\2026-09-23\B1\demo_extension.py` —— **不改 `pipeline\` 里任何文件**，新增一个数据源 + 一个新输出目标

### 验收标准
- [ ] `python demo_extension.py` 退出码 0，产出 `daily\2026-09-23\B1\out.jsonl` 且行数 ≥10；跑前跑后对 `pipeline\` 目录所有文件做 `Get-FileHash -Algorithm SHA256` 对比，哈希全部不变
- [ ] `DESIGN.md` 含全部 5 个小节；`Select-String -Path DESIGN.md -Pattern 'ADR-'` 命中 ≥3 次
- [ ] 至少 3 个公开接口的 `inspect.signature(...)` **真实输出**与 `DESIGN.md` 里写的签名逐字一致（把两组文本并排贴进 `DESIGN.md` 的附录）

## 题 B2（框架 · 快练）｜ 代码考古：CMake 的 PUBLIC / PRIVATE / INTERFACE 为什么要三个关键字

**形态**：B6 代码考古 ｜ **难度**：L2 ｜ **时间盒**：20–30 分钟

### 为什么练这个
`target_link_libraries(app PRIVATE api)` 里的那个 `PRIVATE`，你多半是抄来的。这三个关键字其实是**接口可见性**的设计："我依赖的东西，要不要变成我的调用方也必须知道的东西"。这是框架设计里最贵的一个决定，CMake 用一个关键字把它摆到了台面上——逆推它，比读十篇依赖注入的文章管用。

### 起点与输入
- 读哪个库 / 面对哪个取舍：
  - 本地帮助文本（**优先读这个，别先上网**）：`cmake --help-command target_link_libraries`、`cmake --help-command target_include_directories`、`cmake --help-command add_library`
  - 检索关键词：`usage requirements`、`INTERFACE library`、`transitive dependency`、`target_compile_definitions`
  - 本机工具链（已确认可用）：`cmake 3.31.5` + `ninja` + `clang 19.1.7`，都在 PATH 里
- 工作目录：`C:\Users\15854\ai-lab\daily\2026-09-23\B2\`

### 交付物
1. `daily\2026-09-23\B2\ARCHAEOLOGY.md` —— 一页"它为什么长这样"：三个关键字各自解决什么问题 + **3 条可借鉴 / 3 条不认同**
2. `daily\2026-09-23\B2\lab\` —— 一个最小 CMake 工程（1 个上游库 + 1 个下游目标），能通过改一个关键字让构建从成功变成失败
3. `daily\2026-09-23\B2\evidence.txt` —— 三种关键字各自的 `cmake --build` 原始输出（成功和失败都要，失败那次的报错行必须完整保留）

### 验收标准
- [ ] `cmake -S lab -B lab\build -G Ninja -DCMAKE_C_COMPILER=clang` 配置成功；`PUBLIC` 变体下 `cmake --build lab\build` 退出码 0
- [ ] 把同一个关键字改成 `PRIVATE` 后重新构建，退出码非 0，且报错里出现 `fatal error: '<你的头文件名>' file not found`；这一行完整出现在 `evidence.txt` 里
- [ ] `ARCHAEOLOGY.md` 里"3 条可借鉴 / 3 条不认同"各 3 条，每条一句话且必须落在**接口可见性**这件事上（"CMake 语法很啰嗦"这类不算）；另需一段明确回答：如果只有 `PUBLIC` 和 `PRIVATE` 两个关键字，哪一类需求会表达不出来？给出一个具体场景

### 提示（最多 2 条）
1. **本机 clang 能编译但链接不了**（没有 MSVC 运行库）。所以本题所有目标都用 `add_library(<name> OBJECT <src>)`，**不要用 `add_executable`**——OBJECT 库只编译不链接，正好用来观察头文件搜索路径有没有传递过去。配置命令固定用 `-G Ninja -DCMAKE_C_COMPILER=clang`。
