## 题 A（广度）｜ 写一个 200 行的"崩溃安全"键值存储

**领域**：数据库与存储 ｜ **形态**：A2 复现思想 ｜ **难度**：L2 ｜ **时间盒**：60–80 分钟

### 为什么练这个

所有存储系统的地基只有三件事：**日志、顺序写、恢复**。你写过 Flash 掉电保护，那套"先写日志再改数据"的直觉在这里是同构的——但换到文件系统上，你会第一次亲手撞上"write 返回成功 ≠ 数据已经落盘"这个反直觉事实。这一题的目标不是做出一个 KV 库，而是让你以后看到任何数据库，都能一眼说出它的持久化路径和它放弃的保证。

### 起点与输入

- 语言：Python 最快；想更接近真相就用 C + clang（本机有 clang，无 gcc）
- **先自己想 20 分钟**：日志记录该长什么样？恢复算法怎么写？再查关键词：`write ahead log`、`fsync vs fdatasync`、`crash consistency`、`torn write`
- 工作目录：`C:\Users\15854\ai-lab\daily\2026-09-23\A\`

### 交付物

1. `kv.py`（或 `kv.c`）：支持 `put / get / delete`，数据目录可指定；进程重启后数据还在
2. `NOTES.md`（≥15 行）：你的日志格式、恢复算法、**你主动放弃的一个保证**（例如：不保证并发写、不保证磁盘满时的行为）
3. `crash_test.ps1`（或一段可直接复制的命令序列）：能一键复现"崩溃后恢复"

### 验收标准

- [ ] 正常路径：`put` 后**另起一个进程**执行 `get`，能拿到值
- [ ] 崩溃路径：连续写入 N 条后**强杀进程**（Windows：`taskkill /F /PID <pid>`；WSL：`kill -9`），重启后已确认写入的数据一条不少
- [ ] 对照实验：把 `fsync` 去掉，重复崩溃测试，**观察到数据丢失**，并在 NOTES.md 里解释丢失发生在哪一层
- [ ] 恢复时遇到"写了一半的最后一条记录"不会崩，而是安全丢弃（把文件截断到最后一条完整记录）
- [ ] NOTES.md 里能明确回答：你的方案在什么情况下会丢数据？

### 提示（最多用 3 条）

1. 日志记录可以极简：`[长度][CRC32][payload]`；payload 用 JSON 或自定义二进制都行
2. 恢复 = 从头顺序扫描，遇到第一条不完整或 CRC 不匹配的记录就停在那里，并把文件截断到该偏移
3. 不需要索引，恢复时全量重放进一个内存 dict 就够了

### 进阶挑战

- 加 compaction：当日志文件大于数据量的 N 倍时，重写成一份快照并原子替换
- 用 `fdatasync` / `O_DSYNC` 做对比，给出吞吐数字和解释

## 题 B（框架）｜ 设计一个"命令总线"：让新增命令只写业务

**形态**：B1 接口设计 ｜ **难度**：L2→L3 ｜ **时间盒**：60–80 分钟

### 为什么练这个

框架能力的本质是：**把变化的部分隔离出去，让不变的部分可复用**。这一题给你一组真实的横切关注点（校验 / 权限 / 日志 / 重试 / 结果归一化），要求你把它们从业务里抽出来，并留出扩展点。做完你手上会多一个可迁移的模板：以后任何"流程 + 中间件"的东西都能套这个结构。

### 场景（模糊需求，这是故意的）

一个设备管理程序，命令来源有三种：命令行、HTTP 接口、定时任务。命令分两类：**同步**（立即返回结果）和**异步**（下发后要等设备回执）。现在每个命令里都重复写着：参数校验 → 权限检查 → 写日志 → 失败重试 → 执行 → 结果转成统一格式。20 个命令，20 份重复代码；加一个新命令要复制粘贴 80 行。

### 交付物

1. `DESIGN.md`，必须包含：
   - **调用方视角的示例代码（先写这个，不超过 20 行）**
   - 接口定义（真实语言签名，不是文字描述）
   - 数据流图（ASCII 或 mermaid）
   - 扩展点清单：框架允许别人在哪里插入什么
   - ADR：≥3 个关键决策，每个写"选了什么 / 放弃了什么 / 为什么"
2. 最小可运行实现：≥3 个命令（含 1 个异步）+ 可插拔中间件
3. 扩展点演示：**不改框架代码**，新增第 4 个命令和 1 个新中间件

工作目录：`C:\Users\15854\ai-lab\daily\2026-09-23\B\`

### 验收标准

- [ ] 新增一个命令 = 写一个函数/类 + 注册一行，没有别的改动（用第 3 项演示证明）
- [ ] 中间件按声明顺序执行，且能**短路**：权限拒绝后，后续中间件与业务都不执行
- [ ] 异步命令与同步命令对调用方**接口一致**：调用方不需要 if 判断走哪条路
- [ ] 至少一个中间件被两个以上命令复用
- [ ] DESIGN.md 明确回答：错误怎么传播？超时/取消怎么表达？幂等性由谁负责？

### 提示

1. 先写调用方代码，再倒推接口——这是框架设计最关键的一个动作，别跳过
2. 中间件可以用"函数返回下一个函数"的洋葱模型，也可以用一个 context 对象依次传递；选一个并写清理由
3. 异步 ≠ 多线程：可以是"返回句柄 + 轮询/回调"，重点是**接口统一**

### 进阶挑战

- 命令可组合：一个命令内部调用另一个命令，并说明中间件跑一次还是两次、为什么
- 给总线加 tracing：一条命令的完整链路能被打印出来
