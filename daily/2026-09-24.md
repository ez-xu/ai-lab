### 为什么练这个

你写过裸机固件，"上下文切换""中断""DMA"对你是肌肉记忆；但 Linux 把同一批概念换了一套名字和一套取舍（task_struct、页表与缺页、VFS 与 page cache、cgroup、eBPF）。这一题不是让你学 Linux，而是让你在 60 分钟里把这块领域的**流派与权衡**压成一张能挂在脑子里的地图——而且每个结论都用本机命令验一遍。以后看到任何"调度器 / 内存管理 / 文件系统"的新名词，你都能立刻说出它挂在地图的哪个位置、代价是什么。

### 起点与输入

- 环境：**在 WSL Ubuntu 里执行**（Windows Terminal 输入 `wsl`）。缺工具时：`sudo apt install -y strace linux-tools-generic linux-tools-$(uname -r) bpftrace`

  1. **调度**：关键词 `EEVDF scheduler`（6.6 起取代 CFS）、`sched_ext`、`SCHED_FIFO / SCHED_DEADLINE`；经典系统：Linux CFS/EEVDF、FreeRTOS、Zephyr、seL4

## 题 B（框架）｜ 从三份手写协议解析器里提炼一个"能定位错误"的解析框架

**形态**：B2 抽象提炼 ｜ **难度**：L2→L3 ｜ **时间盒**：50–70 分钟

### 为什么练这个

抽象提炼的完整动作是三步：**先有三份重复 → 找出真正的不变点 → 把变化点做成扩展点**。这一题逼你走完三步，并用"迁移前后 LOC 对比"和"新增协议零改动"两个硬指标证明你提炼对了。难点不在写解析器，而在**决定哪一部分该被固化**：固化错了，第四种协议进来时你就得改框架。这是所有"库 vs 框架"边界问题的原型。

### 场景（模糊需求，这是故意的）

一个设备网关，三年里陆续接了三种设备协议，各写了一份解析函数（每份 100–150 行，全是手写 `offset += 2` 这类游标操作）。现在的问题：

1. 同一个"越界读"bug，在三份代码里各修过一次；
2. 接第四种设备 = 复制一份再改，第五种同理；
3. 现场排障时解析失败只抛 `ValueError("bad frame")`——不知道坏在第几个字节、哪个字段，只能把十六进制贴到群里问人。

**第一步（限时 10 分钟，故意写丑）**：按下面三份规格，各写一份**最短路径**的解析函数（不做任何抽象、允许复制粘贴），放进 `before/parser_a.py`、`before/parser_b.py`、`before/parser_c.py`。这三份是"迁移前"基线，别美化它们。

- **协议甲**：`[0xAA][type:u8][seq:u16 LE][len:u16 LE][payload:len][crc16:u16 LE]`，crc16 覆盖从 `0xAA` 到 payload 末尾
- **协议乙**：TLV 序列，`[tag:u8][len:u8][value:len]`，大端；`0x01`=设备ID(ascii)、`0x02`=温度(i16，单位 0.1℃)、`0x03`=嵌套 TLV（value 内部还是 TLV）
- **协议丙**：ASCII 行 `DEV,<id>,<temp>.<frac>,<ts>\r\n`，字段固定 4 个，`ts` 是 Unix 秒

三份都解析成同一条目标记录：`{"device_id": str, "temp_c": float, "ts": int, "seq": int | None}`

**第二步**：提炼出一个库，让上面三份变成它的三个"描述"，并且第四种协议进来时**框架代码零改动**。

### 交付物

1. `DESIGN.md`，必须包含：
   - **调用方视角的示例代码（第一段就写它，≤25 行）**：展示"定义协议 → 喂字节 → 拿记录 → 拿到可读报错"四件事
   - 接口定义（真实语言签名，不是文字描述）
   - 数据流图（ASCII 或 mermaid）：字节 → 切帧 → 字段 → 校验 → 记录 → 错误
   - 扩展点清单：框架允许别人在哪里插入什么（至少覆盖：新帧切分策略、新字段类型、新校验方式、错误钩子）
   - ADR：**≥3 个**，每个写"选了什么 / 放弃了什么 / 为什么"，且**至少 1 条是"我考虑过但放弃的方案"**
2. 最小可运行实现：`after/` 下的库 + 三份迁移后的协议描述（每份 ≤25 行）
3. 扩展点演示：**不改框架代码**，新增协议丁 `[0x55][len:u8][id:8 bytes ascii][temp:f32 BE][ts:u32 BE][xor:u8]`
4. `MIGRATION.md`：迁移前后对比表（每份 LOC、三份之间还剩多少重复逻辑、修同一个"越界读"bug 现在要改几处）

### 验收标准

- [ ] `DESIGN.md` 里的调用方示例代码**原样**放进 `examples/demo.py` 能跑通（不改一个字），并打印出目标记录
- [ ] `before/` 三份各 ≥80 行，`after/` 三份各 ≤25 行；`MIGRATION.md` 里给出 `wc -l` 的真实前后对比数字
- [ ] 喂一个**截断帧**和一个 **CRC/XOR 校验错帧**，报错信息同时含 **字节偏移 + 字段名 + 期望/实际**（把两条真实报错原文贴进 `MIGRATION.md`）
- [ ] 新增协议丁后，`git diff --stat`（或改动文件清单）显示**框架目录 0 行改动**，只有新增文件
- [ ] 三个协议描述文件里手写游标偏移为 0 处：给出你实际用的 grep 命令与输出（例如 `grep -nE "offset|\[[0-9]+:" after/proto_*.py` 命中 0 行）
- [ ] `DESIGN.md` 的 ADR ≥3 条，且至少 1 条写明被放弃的方案与放弃原因

### 提示

1. 先写调用方代码，再倒推接口。写的时候问自己：**"我要为第四种协议写多少行？"**——如果答案超过 25 行，说明你固化错了地方
2. 三条决策轴，选完写进 ADR：① 字段描述用**数据**（表 / 装饰器）还是用**子类覆写**；② 解析失败用**异常**还是**返回值**；③ 帧切分（framing）与字段解析**要不要分开**（分开的代价是多一次拷贝，好处是协议丙这种没有长度前缀的流式协议也能进同一个框架）
3. 错误定位的关键是让**游标对象自己带着"当前字段名 + 起始偏移"**，而不是在每个字段解析处手写 try/except——把这件事做进不变点，就是这一题的核心收益

### 进阶挑战

- 给框架加"流式喂入"：`feed(bytes)` 可分多次调用，协议甲/丙要能跨包边界切帧（提示：不变点从"完整 buffer"变成"可增长的游标 + 状态机"）
- 用 `pytest.mark.parametrize` 把三份 before 实现与 after 实现跑同一组坏帧语料，证明行为等价；若不等价，列出差异并解释哪边是对的
